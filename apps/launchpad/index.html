API Developer Documentation

01. Overview

The **OmniVis API** is built using Hono and runs serverless on **Cloudflare Workers**. It relies on **Cloudflare D1 SQL database** to handle diagram and presentation persistence, and supports dual OpenAI and Anthropic engines.

02. REST Endpoints Summary

Method Path Scope Description
GET /health Public Gateway health verification check
POST /api/ai/generate/slides AI / BYOK Generate JSON slide contents
POST /api/ai/generate/diagram AI / BYOK Generate Mermaid code representations
GET /api/presentations Public Fetch presentations by user reference
POST /api/presentations Public Save / Update presentation slides

03. Bring Your Own Key (BYOK) Headers

Both AI generation endpoints support client-side API key injection. You can provide credentials via standard requests using headers or JSON parameters.

# Endpoint Call Example
POST /api/ai/generate/slides
Headers:
x-openai-api-key: sk-proj-yourOpenAiKeyGoesHere
x-anthropic-api-key: sk-ant-yourAnthropicKeyGoesHere
Body (JSON):
{
"prompt": "Create an architectural breakdown of microservices",
"slide_count": 5,
"provider": "openai"
}

04. CORS Configuration

The backend allows requests from **`omnivis.github.io`** and local developers (`localhost:3000`, `localhost:5173`) natively. If deploying custom clients, ensure domain entries are appended inside the Worker's **`ALLOWED_ORIGINS`** binding in `wrangler.toml`.
